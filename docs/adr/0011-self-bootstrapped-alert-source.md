# 自举告警源：以系统自身运行态作为真实告警输入

上下文：系统至今的**全部输入都是自产的**——语料由本项目生成、query 来自自己的脚本、压测流量也是自己打的、告警靠 `--storm` 模拟。结果是：在合成场景上近乎完美，却从未接触过任何不可预测的输入，迭代的信息增益趋近于零。ADR-0004 早就立好了 `source: alert|manual` 的契约与字段，但"告警生产者"一直缺位；谱系定位表里 M3「告警接入」因**无真实监控源**按硬约束挂起。关键判断是：该缺口缺的是"真实输入"，而真实输入不必然来自外部系统——项目自身运行史就是一份真实、带 root cause、可对提交与台账核验的事件流。

决策：新增**自举告警生产者**（`offline/alert_producer.py`，常驻或单轮）。它只读既有观测面（`/api/v1/admin/state` 的 health / runtime.degradation / metrics.* 与配额面），按五条规则判定异常（依赖 DOWN、熔断或降级档位脱离 L0、上游限流、检索路劣化、拒答与降级直出激增），命中即以 `source=alert` POST 回既有入口 `/api/v1/copilot/chat/stream`——**不新增后端接口、不新增指标、不改权限模型**。配套三项：① 告警主体用独立账号 `sre-watcher`（`role=platform` + `auth_level=3`，配额与审计主体与演示账号隔离）；② 审计业务行新增 `source` 字段（与 `via` 正交：via 答"从哪个协议面进来"，source 答"人工还是告警触发"，并把重载收敛为单一入口，防止新字段在旧调用点上静默缺省）；③ 语料补齐 7 起真实事故的复盘+处置（`pm/rb-201..207`）、依赖不可用通用处置单（`rb-208`）与账号库损坏事故（`pm-104/rb-105`）。

理由：① 沿用单链路使实现成本最低（生产者只是一个读观测面、打既有端点的进程）；② 事件是真的——真触发、真根因、可对 commit/台账/现场日志核验，来源是自身运行史而非编造；③ 它解开了 M3 挂起项：硬约束是"没有真实告警源"，自举**换了一个源**，而不是"违规去做 absent 的 adapter"。④ 护栏齐备才允许常驻：每规则冷却、每小时上限、配额保留线（留给人用）、计数器复位识别、单轮失败不退出、出口走 `assert_local` 白名单。

备选与否决：**等真实监控源接入**（无限期挂起＝永不触发，否决）；**做告警 adapter / 独立摄入管道 / 告警持久化实体**（违反 ADR-0004 单链路纪律，且当前无真实源可接，否决）；**仅让人工构造告警**（回到自产输入，不解决根本问题，否决）；**给生产者开放写操作**（属谱系表 ⑤ 处置闭环，触发线未到，明确不做）。

后果：系统第一次拥有"自己发现、自己上报、自己检索、给出处置"的完整链路证据，且该证据可被任何人重放；审计与面板从此能回答"这条请求是系统自诊断还是人发的"（新增字段向后兼容，消费端按 `.get` 解析）。代价是引入一个常驻进程及其护栏，外加一条**已知盲区**：网关自身不可用时生产者无法经 `/state` 自证，只能记 `unreachable`——单进程自举的固有边界，已在交付台账中显式登记，不假装覆盖。**安全边界**：`source` 是客户端自述元数据，不参与鉴权与配额决策，仅用于可观测与窗口分档，**不能作为来源溯源的证据**（伪造 source 不获得任何权限）。同一轮实测还更正了 OPS.md 的账号 CLI 并发口径：容器 bind mount 形态下 H2 锁不可靠，CLI 必须与容器网关串行（事故 `51103_H2_CONCURRENT_WRITE_CORRUPTION`）。
