# 生成层强制分层：verbatim 走出口硬护栏，断言语态走软约束上限

状态：accepted（2026-09-13，生成质量包 grill Q2/Q3，用户逐题拍板）

上下文：第五轮复现两处生成层缺陷——①L1 用户一句话即可让助手逐字倒出**其有权看到**的
chunk 原文（实测 304 字重合，台账 P2-4）：这不是越权泄露，是"排障助手退化为文档导出器"
的产品叙事破防；②无错误码的泛化症状长文被自信锚定到具体事故编号（断言语态）。候选设卡点
三层：prompt（模型自觉）、流结束后事后检测（已渲染字符收不回）、流式出口代码（硬）。
台账纪律明言"验收标准是引擎层过滤，而非模型自觉"（越狱用例定义）——但语态的"自信与否"
在出口没有确定性判据，强行上结构化门控需改协议面。

决策：**按判据的客观性分层设卡，各层上限成文**。
1. **verbatim（客观判据=可数的连续重叠）→ 双层，硬层兜底**：
   PromptAssembler 规则 5（仅总结/引语≤80 字/拒绝逐字导出）+ `VerbatimStreamFilter`
   句级出口硬护栏：token 攒到句末（`。！？；!?;` 换行、英文 `. `）下发，下发前
   「已吐尾部 carry(160) + 待发句」与参考原文做最长公共子串，>80 字整句替换占位话术。
   设卡一处即可：L1/L2 写入与 Single-Flight 分发消费的均为掩码版载荷——缓存回放与
   follower 天然干净；/api 与 /v1 双协议面同链路自动同护栏（ADR-0007 一致性不破）。
   掩码事件落审计 `verbatim_masked`（仅 >0 携带）+ OpsMetrics 计数入面板。
2. **断言语态（主观判据=句式自信）→ 软层 + 探针锁最恶劣形态**：query 无强标识符
   （`EsSearchService.hasStrongIdentifier`，词法与快路径同源）时条件注入规则 6
   （假设语态开口、编号只可作可能性示例禁锚定为结论）；验收=泛化症状 2 变体 ×3 连跑
   正则断言。正则判据的脆弱性**定性为本层设计上限，非缺陷**（grill 裁定）；升级触发线
   入 OPS 债务闹钟表：任何一次被真人/QA 复现、且落在探针正则覆盖之外的断言式编号回答
   → 立项输出结构化门控（模型按标注输出置信、渲染层依标注 gating）。
3. **阈值 80 字单一口径**：规则 5 的引语配额与 `VerbatimGuard.MAX_OVERLAP_CHARS` 同数，
   改一处必改另一处（单测边界 80 过 / 81 拦锁死）。

否决项：纯 prompt（验收不可锁死，违引擎层纪律）；纯事后检测（救不回已渲染字符，对症状
零改善）；把滑动窗口升格为第二穿透闸门（违 ADR-0003/0008 单飞主闸门纪律——窗口是计数，
见 CONTEXT.md 词条修订）。

后果：
- SSE delta 粒度从 token 变句（打字机变"句式机"；面板回放本就句级分片，观感一致）。
  TTFT 口径改为**首个下发帧**——数字变大是诚实化，不是回退。
- carry(160) 必须 > 阈值，否则跨句拼接（表格式导出）漏检——常量旁注释即锁。
- 软层的规则 6 会让弱问题语气变保守（防断言收益的价格）；强标识符问题行为逐字不变。
- 服务名明确**不进**强标识符判据：服务名词表=第二真相源且随 reingest 漂移（grill Q3 裁定）。
