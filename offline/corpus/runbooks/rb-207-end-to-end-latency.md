# 端到端延迟远大于服务端耗时排查手册（51207_HOSTPORT_PROXY_LATENCY）

## 适用症状

- 客户端测到秒级延迟，服务端审计 `took_ms` 只有毫秒级，两者相差两三个数量级
- 延迟**恒定**：不随并发、数据量、时段变化，像是每个请求都被加了固定成本
- 换直连 IP（127.0.0.1）无改善，排除域名解析与 IPv6 假说
- 只有经容器端口映射的形态慢，宿主裸进程形态正常

## 排查步骤

### 第一步：对齐测量点（先别猜原因）

1. 同时记录三个数字：客户端端到端、服务端处理耗时（本系统看审计 `took_ms`）、
   以及二者差值（即链路开销）
2. 差值恒定 → 环境链路问题；差值随负载变化 → 应用或依赖问题
3. 明确写下"性能口径以哪个为准"，后续所有结论都基于同一测量点

### 第二步：分型定位链路开销

4. 宿主裸进程直跑（不经容器端口映射）对比一次：若恢复正常 → 定位到端口转发链路
5. 容器内测自身（`docker exec` 里 curl 本机端口）：若也快 → 确认是宿主↔容器转发，而非容器网络本身
6. 排除其他固定开销来源：代理设置、杀软/EDR 拦截、DNS 超时、TLS 握手

### 第三步：判定是否需要修

7. 若为平台固定开销且不随负载变化 → 判为**环境项**，不改应用代码，改测量与演示方式
8. 若为客户真实链路（生产环境同样存在）→ 才进入性能优化流程

## 止损操作

1. 性能口径切换到服务端 `took_ms`，并在报告里标注测量点（避免继续传播"系统慢"的错误结论）
2. 演示/录屏若必须展示端到端时间 → 改用宿主裸进程或 host 网络模式
3. 把结论写进运维文档的"环境项"清单，注明数值特征（恒定偏移，本机约 2.05s）
4. 若调用方按端到端时间设了超时，重新评估其超时阈值是否被环境开销吃掉

## 升级路径

- 恒定偏移在**宿主直跑**形态下仍存在 → 不再是端口映射问题，转查客户端侧（代理/杀软/栈实现）
- 需要容器形态的端到端性能基线 → 属部署形态评估，需与容器网络方案一并权衡（另立决策）
