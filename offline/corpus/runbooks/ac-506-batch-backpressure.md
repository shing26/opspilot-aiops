# 批处理反压（夜间对账任务）

## 适用症状

- 凌晨对账窗口批任务处理速率断崖下跌，`52005_BATCH_BACKPRESSURE` 持续上升；
- 白天窗口偶发（与上游财务系统联调时段重叠时）。

## 排查步骤

1. 先看消费端再看生产端：反压的直接触发条件是队列水位超阈值，根因通常在消费端——
   核对批处理 worker 池的活跃数与挂起数；
2. worker 挂起集中在外部依赖调用（财务接口 / 邮件网关）→ 对端限流，核对本方
   QPS 是否超过双方约定的联调配额（财务接口日间 200/s、夜间 800/s）；
3. worker 无挂起但速率仍低 → 检查批大小自适应逻辑是否被坏消息卡住（毒消息：
   单条解析失败反复重试，会占住整个批次槽位），毒消息表 `batch_dlq` 行数确认；
4. 全队列堆积且无毒消息 → 大概率是锁竞争：对账表的批次状态更新与业务写入行锁
   冲突，错峰重排。

## 止损操作

- 毒消息：手动转入 DLQ（工具 `batch-replay --skip-dlq`），恢复整批吞吐；
- 夜间配额不足：申请临时联调窗口挪移至 04:30 后（避开财务日切批）。

## 常见误判

- 把毒消息卡批误判为"数据库慢"——DLQ 表有增量即可排除 DB 因素。
