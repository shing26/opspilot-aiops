# 下单库超时（Acme 租户 · 托管 RDS 代理链路）

> 本文档适用于 tenant-acme 的 acme-order-service。集团内部租户的同类手册（订单中心
> 直连 MySQL 场景）处置动作**不适用**本租户——本租户数据库经托管代理层接入。

## 适用症状

- 下单接口 P99 突刺，日志出现 `50012_DB_TIMEOUT`；
- 应用侧连接池指标正常但获取连接变慢（代理层排队特征）；
- 同时段 `52011_RDS_PROXY_STALL` 计数上升。

## 排查步骤

1. 确认超时落在代理层还是数据库层：查代理侧 `proxy_backend_latency` 与
   RDS 控制台 `CPU/IO` 面板，代理延迟高而库侧空闲 → 代理链路问题；
2. 代理链路异常时检查同可用区是否有批量备份任务（Acme 托管实例的备份窗口默认
   03:00-04:00，会抢占代理线程）；
3. 库侧压力型超时：在 RDS 慢日志筛 `acme_orders` 表近 10 分钟语句，重点看
   `SELECT ... FOR UPDATE` 的锁等待时长；
4. 核对应用连接池 `maxLifetime` 是否大于代理空闲断开阈值（30 分钟）——大于则会
   拿到"半关闭"连接，表现为间歇性超时而非全量超时。

## 止损操作

- 代理层 stall：在托管控制台执行「代理重启」（秒级闪断，比换绑连接池快）；
- 锁等待：kill 持锁会话（控制台「实例会话」页操作，需 DBA 审批）；
- 全量超时降级：下单切「写缓冲队列」开关（配置中心 key：`acme.order.write-buffer`），
  恢复后按队列顺序补写。

## 常见误判

- 把它当成内部租户手册里的"连接池耗尽"处理——本租户连接池告警阈值不同（80%），
  池水位 70% 时问题大概率不在池；
- 备份窗口期超时误判为故障，调低隔离级别——应改约备份窗口而非动隔离级别。
